## 信息依据

| 信息 | 以什么为准 |
| --- | --- |
| 应用 ID、版本、SDK 要求 | [app/build.gradle](../app/build.gradle)、[Manifest](../app/src/main/AndroidManifest.xml) |

主题文档描述当前约定，历史记录描述当时事实。用户实机反馈应明确标注来源；协议模拟、AVD、实机之间不能互相替代。验证记录中的旧界面、按钮或默认值不作为当前需求。

## 维护规则

- README 服务首次了解项目的人：只保留介绍、快速上手、构建入口和文档导航。中文与英文内容同步，顶部互相链接；详细技术文档暂用中文。
- AGENTS.md 服务执行任务的 AI：保持简短，提供任务路由、必要约束与检查入口，详细知识放在相应主题。
- 每个主题只维护一份当前说明。新增功能先更新归属主题；需要新增主题时，同时加入本索引和 AGENTS 的任务路由。
- 验证记录放在 `docs/validation/<version>.md`，同时更新验证索引。记录实现范围、实际环境、命令或阶段、结果、未覆盖边界；没有运行的检查不能写“通过”。
- 不为普通文案调整新增版本记录，不把全部旧记录重复抄到当前文档。修正旧报告事实时保留“当时”与“后续反馈”的区别。
- 文档用仓库相对链接和源码文件名定位，避免依赖易变行号。示例用占位地址，设备序列号和下载地址由当前任务确定，不写入私人部署信息。
- 改目录时同步修复所有引用；改脚本参数、类职责、配置字段、server 版本或发布流程时同步更新相关主题。运行 `python3 scripts/check-docs.py`，检查本地链接、Markdown 代码块、README 互链、索引覆盖和验证阶段说明。外部网页与页内锚点由相关改动人工核对。

## 按改动更新

| 改动 | 应一起维护 |
| --- | --- |
| 用户能看到的功能、操作或限制 | 使用说明；涉及简介 / 快速上手时更新两份 README |
| 模块边界、协议、关闭顺序、远端服务 | 架构与约束；涉及兼容性时更新排障 |
| 配置字段、默认值、权限、语言 | 配置与数据；配置兼容测试或对应 UI 专项 |
| 工具链、构建命令、验证阶段 | 开发 / 验证指南；可执行的脚本入口 |
| 版本、签名、依赖或 APK 交付 | 发布指南、第三方说明、适用的验证记录 |
| 重复出现的开发或验证错误 | 修复脚本、检查工具或操作流程，再记录原因与验证方式 |

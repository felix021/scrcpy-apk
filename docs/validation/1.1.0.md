# 1.1.0 无线调试配对

[验证索引](README.md) · [使用说明](../usage.md)

## 实现范围

- Android 11+ 被控端的二维码 / 六位配对码配对，以及后续 STLS / TLS 1.3 连接；传统 TCP 和 USB 继续共用持久化 RSA 身份。
- 主控设置可编辑本机名称，预览远端实际名称；空白转为下划线，避免 Android 只显示第一段名称。
- 配对端口与连接端口分开，优先发现连接端口，允许手动填写；取消、切换模式和关闭页面终止旧任务。
- 配对弹窗沿用深色样式；中英文与竖屏 / 左右横屏适配，QR 区域保持清晰，不覆盖滚动渐隐。
- 低延迟解码选项只对声明支持的解码器启用，修复 Android 11 AVD 解码器配置失败。

## 实际环境与证据

开发验证日期为 2026-11-08，主控为 Android 11 x86_64 AVD，被控端为 Android 16 x86_64 AVD。设备与 adb server 明确归属本任务，没有操作其他会话的目标或真实手机。

- Debug / Release 构建、四种 ABI 原生库编译、34 项 JVM 单元测试通过；release lint 无错误，保留项目已有警告。
- 六位配对码完成真实系统配对、TLS 视频首帧、远控设置与确认断开。
- QR 专项解码界面实际显示的二维码，再调用远端系统 QR 配对入口，通过临时 NSD / TCP 代理完成配对、自动发现连接端口与真实视频首帧。
- 错误六位码在加密配对校验阶段被拒绝，可切换模式继续操作；单纯网络失败不作为错误码验收证据。
- 从设置界面修改名称，Android 配对列表确认完整保存 `My_Android_Client`；与旧 RSA 身份共用，不更换密钥。
- 英文、中文各检查竖屏、左横屏和右横屏，实际截图中的二维码可解码、底部按钮完整可见。
- 传统 TCP 连接取得真实视频首帧，设置与确认断开正常。
- 最终签名 APK 的配对码、QR、传统 TCP 与远端名称专项再次通过。最终 APK 为 1.1.0（versionCode 14）、非调试 release 构建，原签名证书一致；APK 和源码的私人路径 / 凭据检查通过。

## 验证中处理的问题

NDK 加密库独立编译后链接 JNI，避开 AGP 7 对 BoringSSL 多输出目标的限制；Gradle / AGP 版本保持不变。无线脚本先构建后安装，构建失败即停，防止使用旧 APK。目标系统的服务发现日志包含历史端口，脚本只接受当前活跃 Advertiser ID 的端口。

AVD 网关转发的 TLS 曾提前关闭，改用测试自有的 adb reverse。系统 Wi-Fi 短暂断开会关闭无线调试，相关中断单独保留日志，恢复目标 Wi-Fi / 无线调试后补跑；脚本现在区分无线调试中断与应用断言失败，不靠修改生产协议掩盖测试环境问题。注册代理在远端广播出现前建立，避免同一测试混入两条网络路径；退出时只清理自己的端口、注册和临时 fixture。

## 边界

这些结果覆盖真实 Android 系统配对服务与原生视频链路，未使用实体 Android 摄像头扫描。目标 AVD 的调试镜像未启用完整 RSA 授权限制，不能据此声称所有厂商的证书授权策略均已通过。USB 实机与真实麦克风 / 扬声器本轮未重新验收，既有用户反馈不能替代本轮专项。

APK、二维码截图、六位码、设备地址与日志均保存在 Git 之外。公开仓库只保存源码、固定依赖校验和、许可及上述脱敏结论。

# 1.0.0 验证记录

首个正式 GitHub Release。应用版本为 `1.0.0`，versionCode 为 `13`，包名保持 `cn.felix021.scrcpy`。本次未改变远控功能，改为交付非调试的 release 构建，并为验收脚本增加 `--apk`，确保安装、麦克风注入辅助步骤均使用指定的最终 APK。

## 构建与签名

JDK 11、Android SDK 31，执行：

```bash
./gradlew :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease :validation:probe:assembleDebug --offline
python3 scripts/check-docs.py
```

构建成功，30 项 release JVM 测试全部通过，release lint 无错误。APK Manifest 未开启 `debuggable`，安装后 `run-as` 也因不可调试而被拒绝。

为支持早期版本覆盖升级，继续使用原有 Android debug 签名身份；release 构建本身关闭调试，不引入新的商店签名。证书 SHA-256：

`1838e39e3707c6381540966d240dc4675f61553b0214d3ea3b9f17f9c094f064`

最终 `scrcpy-apk-1.0.0.apk` 的 SHA-256：

`f62ce1dce5dc702d6ce70cbe8288024c7face6172208034400003dec9643584f`

APK 只包含源码许可、第三方许可与已固定哈希的 scrcpy server 三项 assets，不包含本机配置或签名私钥。APK 与 `SHA256SUMS` 作为 GitHub Release 附件，生成产物不进入 Git。

## 最终 APK 的设置验收

两个专用 Android 14 AVD 上，以 `--apk` 指向 release 包运行 `--phase app-settings`，退出码为 0：

- 从已安装的 0.12.0 覆盖升级成功，签名保持一致。
- About 显示 1.0.0 (13)，中英文、跟随系统和语言重启持久化正确。
- 切换语言保留未保存表单、暂时无效的数字输入和 USB 连接方式。
- 左右横屏弹窗可操作、底部按钮固定、浏览器收到正确仓库地址，系统 Back 可关闭弹窗。

## 最终 APK 的双向声音验收

对同一 release 包运行 `--phase audio-runtime`，通过真实输出采集和远端普通 `AudioRecord` 测量四种组合；切换期间视频进程与连接保持不变：

| 远端声音播放 | 本机麦克风转发 | 本机 1499 Hz 幅度 | 远端录音 997 Hz 幅度 |
| --- | --- | --- | --- |
| 关闭 | 关闭 | 0 | 0 |
| 开启 | 关闭 | 288 | 0 |
| 关闭 | 开启 | 0 | 12016 |
| 开启 | 开启 | 286 | 12016 |

拒绝录音权限后保持原视频，未启动录音；关闭声音与麦克风后，相应服务退出，结束会话后执行清理并恢复测试前媒体音量。

## 中断与验证边界

首次声音验收因辅助步骤仍固定读取 debug APK 路径而中断，已统一改为 `--apk` 选择的文件。随后一轮因被控 AVD 进程退出而中断，退出原因未确认，该轮不计为完整通过；恢复同一 AVD、恢复其原旋转与音量后，从头补跑声音专项。验收清理也保留原始错误，避免设备失联时恢复音量的错误覆盖首个失败。

本次为 AVD 上最终 release 构建的设置与声音验收，不声称重跑所有历史专项。USB 功能此前由用户完成实机验收，本轮未新增 USB 实机检查，见 [0.11 记录](0.11.md)。历史功能与用户反馈见 [验证索引](README.md)。
